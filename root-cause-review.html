1. Literal escape text is changed before editing

The fixture supplied the eight ASCII characters x\u0041y. Its UTF-8 bytes were 78 5c 75 30 30 34 31 79. The client dispatched xAy to Edit, and disk bytes were 78 41 79. A single ordinary JSON parse preserves the supplied backslash; it does not explain this extra rewrite.

Ten controls were run on each tested version. Four inputs were changed and six were preserved. Every resulting file matched the input shown at tool dispatch. This places the mutation before Edit's file-writing logic. The downloaded 2.1.312 implementation contains an input-normalization function that invokes a recursive Unicode-repair pass: it decodes eligible escape sequences, skips doubled backslashes, has a whole-string Windows-path guard, and excludes some controls. Its behavior matches the measured controls.

Practical effect: source text, documentation and test fixtures intended to contain literal escapes can be changed into actual characters, including line separators. The tests demonstrate byte mutation, not a malicious exploit or a production incident. A potential fix is to preserve ordinary JSON string semantics and make extra repair explicit; that proposal is not a vendor patch.

2. Distinct MCP calls can receive the same result file

A dummy MCP server returned ten distinct tagged payloads. In the first burst, ten calls were pointed to three files; seven calls received a file containing another call's tag. The stored files contained the winning results. This was substitution through a shared path, not a demonstrated later-write overwrite.

The second burst did not collide. That result is retained: the failure depends on clock timing, and these small trials do not estimate a production failure rate. All thirty call-to-file associations were checked against the actual saved content.

Root cause in the tested release: the MCP persistence handler builds its file stem from the server name, tool name and Date.now(), without a unique tool-call identifier. The storage helper uses exclusive creation, but after an existing-file error it accepts a regular singly-linked file and returns its path without comparing content identity. Together, those choices allow distinct same-millisecond calls to share the first successful file.

A potential fix is to include the tool-use identifier in the saved name and treat unexpected collisions as errors or verify identical content. Neither fix has been implemented or tested in Anthropic's product by this review.

3. Permission test remains unresolved

The standalone write and two compound-write variants were denied, and no canary file was created. However, the permitted read-only Git command failed inside Git Bash with NtCreateDirectoryObject access denied. Since the positive execution control failed, this environment cannot provide a valid end-to-end test of that report. The absence of a marker is not evidence that the reported bypass is fixed.

62 evidence-consistency checks passed. These checks reconcile supplied arguments, dispatched inputs, disk bytes, tool-result identities, release provenance and implementation anchors. Passing evidence checks does not mean the product passed its intended invariants: two defects in client behavior were observed. Initial Write-tool testing was excluded because the tool was unavailable in that configuration. Windows extended-length paths were required to inspect saved MCP files correctly; missing-file observations were not treated as substitutions.
